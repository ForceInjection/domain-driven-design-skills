# DDD Discover

## 使用时机

- 需要快速对齐核心业务流程与领域边界线索。
- 需求已明确（来自 `ddd-scope` 或用户直接提供），需要探索领域内部发生了什么。
- `ddd-contexts` 报告"术语冲突不可调和"时，作为回溯目标重新执行。

## 输入要求

- **必需**：业务场景描述（用户故事、PRD、工单、或 `ddd-scope` 的输出均可）。
- **可选**：关键参与方与外部系统、业务约束与非目标（来自 `ddd-scope`）。

## 流程

1. **列举事件**：以"已发生的事实"为视角，用**过去时**命名领域事件（如 OrderPlaced, PaymentReceived）。
2. **补全命令**：为每个事件补充触发它的命令、发起者、关键输入数据。
3. **排列时序**：将事件按时间线组织，识别分支、回滚、异常路径（至少覆盖 1 条主路径 + 2 条异常路径）。
4. **标注热点**：标记高频事件、强一致性点、跨系统边界、性能敏感点、合规检查点。
5. **生成歧义清单**：记录术语冲突、状态不明确、职责归属模糊的问题，标注"谁必须确认"。
6. **输出边界线索**：从事件聚类与热点分布中提取初步的能力分组与上下文边界候选。

## 输出

| 工件         | 结构要求                                                            |
| :----------- | :------------------------------------------------------------------ |
| 事件流表     | 表格：序号、事件名（过去时）、触发命令、参与者、输入/输出、异常分支 |
| 命令候选清单 | 表格：命令、发起者、期望结果、幂等性要求                            |
| 事件候选清单 | 表格：事件、关键字段、是否跨上下文、是否对外发布                    |
| 热点标注     | 列表：一致性热点、集成热点、性能热点、合规热点                      |
| 歧义清单     | 表格：歧义点、影响范围、需确认方、建议决策                          |
| 边界线索     | 列表：初步能力分组与潜在上下文边界                                  |

## 校验清单

- [ ] 事件使用过去时命名，业务可理解
- [ ] 至少覆盖 1 条主路径 + 2 条异常/回滚路径
- [ ] 热点中明确标注了跨系统边界与强一致性点
- [ ] 歧义清单中每条都标注了"谁必须确认"
- [ ] 边界线索可被 `ddd-subdomains` 直接消费

## 回溯触发

- 本 Skill 被 `ddd-contexts` 触发回溯：当 > 5 个术语存在不可调和的跨上下文冲突时，说明领域理解不足，需重新发现。

## 示例

```text
@ddd-discover
基于以下 scope 输出，帮我做领域发现：
- 问题：订单售后流程混乱
- 目标：支持退款、换货、投诉处理
- 非目标：不涉及正向下单流程
请输出事件流表、命令/事件候选、热点标注与歧义清单。
```

# Aggregate Design

## 使用时机

- 需要把业务规则落到代码结构：聚合根、实体/值对象、不变量与事务边界。
- 需要减少“巨型模型/巨型事务”，控制一致性与并发冲突。

## 输入要求

- 事件流与命令候选（阶段 1）。
- 限界上下文目录（阶段 2）。
- 跨上下文契约与失败模式（阶段 3，如已完成）。

## 流程

1. 从命令与事件中提取“必须保持为真”的业务不变量集合。  
2. 按不变量聚类对象，提出聚合候选，并明确聚合根。  
3. 定义聚合边界规则：外部只能持有聚合根引用，跨聚合引用用 ID。  
4. 为每个聚合定义命令边界：哪些命令由该聚合根处理，前置校验是什么。  
5. 定义一致性策略：聚合内强一致，跨聚合采用最终一致（事件驱动/补偿）。  
6. 输出仓储接口草案与事务边界建议（每事务修改一个聚合为默认规则）。  

## 输出

| 工件 | 结构要求 |
| :--- | :--- |
| 聚合清单 | 表格：聚合、聚合根、包含对象、关键不变量、关键命令 |
| 不变量清单 | 表格：不变量、触发命令、校验位置、失败行为 |
| 事务边界建议 | 列表：默认规则、例外条件、并发/锁策略 |
| 跨聚合一致性策略 | 表格：场景、事件、补偿、幂等、重试 |
| 仓储接口草案 | 表格：聚合、仓储方法、语义说明、查询边界 |

## 校验清单

- [ ] 每个聚合都至少对应 1 个明确不变量
- [ ] 聚合边界能解释事务边界，且默认“每事务 1 聚合”
- [ ] 跨聚合一致性已给出事件与补偿策略

## 常见陷阱

- 以数据库外键关系划聚合，导致聚合无限膨胀。
- 聚合根贫血，不变量散落在应用服务与控制器。

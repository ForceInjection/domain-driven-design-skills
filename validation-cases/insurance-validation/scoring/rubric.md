# 评分规范（Rubric）— 保险承保与理赔验证案例

> 本案例为**无规范参考**案例（领域无成熟开源 DDD 参考实现），评分采用**专家评审制**：不设真值锚点（A 类锚点依赖参考实现，不适用），改为四类判据，由评审者依据工件内容逐条判定，每项结论必须引用具体工件条目作为证据。

## 1. 权重表（按 Skill 在流水线中的影响力）

| Skill                   |   权重   | 理由                                   |
| :---------------------- | :------: | :------------------------------------- |
| ddd-scope               |   1.0    | 入口收敛，影响后续输入质量             |
| ddd-discover            |   1.5    | 事件流是全部后续阶段的原料             |
| ddd-subdomains          |   1.0    | 战略分类，影响上下文设计               |
| ddd-contexts            |   1.5    | 语言与边界，决定一致性                 |
| ddd-context-map         |   1.5    | 集成与失败模式                         |
| ddd-aggregates          |   2.0    | 战术核心，不变量质量直接影响建模正确性 |
| ddd-domain-interactions |   1.5    | 事件/服务/仓储完整性                   |
| ddd-model-review        |   1.0    | 质量门禁与回溯判定                     |
| **合计**                | **11.0** |                                        |

## 2. 评分标准（0–4 五档）

| 分档 | 含义                                |
| :--: | :---------------------------------- |
|  0   | 未产出                              |
|  1   | 结构错误（未按 SKILL 输出要求组织） |
|  2   | 结构对，但关键概念缺失              |
|  3   | 命中主要概念，有少量遗漏或偏离      |
|  4   | 四类判据全部命中，且无重大偏离      |

## 3. 四类判据（替代真值锚点）

### A. 业务完整性

模糊简报（`00-fuzzy-prompt.md`）中的以下要素是否被工件全覆盖：

- 角色：客户（个人/企业）、经纪、核保人、查勘员、理赔员、审批人、财务、管理层、监管
- 流程：投保 → 报价 → 承保 → 出单 → 批改 → 续保/中止 → 报案 → 查勘 → 定损 → 审批 → 支付 → 追偿
- 异常：巨灾高峰、重复/虚假报案、材料迟到、批改与理赔并行冲突、欺诈调查、支付失败
- 约束：监管报送、多级审批、高峰并发不可丢件

### B. DDD 原则合规

- 聚合边界以不变量为依据，1 事务 1 聚合；外部引用有生命周期再审视结论
- 术语在上下文中含义唯一；跨上下文同名不同义已翻译/重命名
- 事件过去时、无技术词；跨上下文事件有幂等键
- 谓词型业务规则显式抽取为 Specification（若有）

### C. 内部一致性

- 每个 Skill 的输出可被下一阶段直接消费（编号/命名/术语沿用）
- 事件在 discover 提出、在 interactions 正式定义、在 review 中被核对，链条完整
- 上下文/聚合/事件三方引用关系无矛盾

### D. 正向越位识别

- 超出简报要求的合理增强（如巨灾批量处理模式、报案聚合、审批升级链）
- 不认定任何"偏离"为错误，除非违背判据 A/B

## 4. 评分规则

- 每档得分必须有证据引用（工件文件 + 章节/条目）。
- **保守原则**：涉及"未经业务方/外部确认"的判定（如歧义决策、边界划分的替代方案），得分不超过 3。
- 加权总分 = Σ(得分 × 权重) / (4 × Σ权重) × 100%。
- 本评分制的分数**仅反映专家评审视角下的相对质量**，与 Cargo 案例的有真值分数不可直接对比。

## 评分维度与得分

评分标度：0=严重缺失、1=明显缺陷、2=可接受但有改进空间、3=达标、4=优秀。

| 维度 | 得分 | 评语 |
| :--- | :--- | :--- |
| 1. 范围与非目标清晰度 | 4 | 目标 5 条、非目标 4 条、约束 9 条，结构完备；非目标与外部依赖均显式。 |
| 2. 事件风暴覆盖度 | 4 | 主路径 14 步 + 3 组异常分支（A/B/C），含错卸与迟到两类硬场景。 |
| 3. 术语一致性（跨上下文） | 3 | `Shipment` / `HandlingFact` / `TrackingView` 在各上下文中定义唯一；反义词表已列出 5 类常见污染。尚未做全局术语冲突数值计算——粗看冲突率 < 10%。 |
| 4. 上下文边界 | 3.5 | 4 个上下文 + 1 个假设（PortDirectory），责任划分清晰；ADR-01/02/03/04 覆盖关键决策。扣分项：客户通知未独立成上下文。 |
| 5. 上下文映射合理性 | 4 | 关系矩阵 + ACL 策略 + 失败降级完整；Customer-Supplier / OHS / ACL 三种模式均出现。 |
| 6. 聚合与不变量表达率 | 3.5 | 不变量 11 条，强约束 10 条；I-1~I-11 清晰对应聚合；Route 是否应单独聚合仍可讨论。 |
| 7. 领域事件与交互 | 4 | 发布-订阅表、幂等键、消息流三场景均到位；未遗漏迟到回放这一最难场景。 |
| 8. 可回溯到业务目标 | 4 | 每个核心能力 C1~C13 与目标 1~5 可映射；非目标未被静默触碰。 |
| **加权综合** | **3.8 / 4** | 整体结构均衡、无明显断链；小幅改进在术语全量核对与客户通知上下文独立化。 |

## 回溯触发判定

对照 `ddd-model-review` 的典型触发条件：

| 触发条件 | 当前状态 | 是否触发 |
| :--- | :--- | :--- |
| 聚合边界与上下文边界矛盾 | 未发现（Shipment 在 Booking，HandlingFact 在 Handling，TrackingView 在 Tracking） | 否 |
| 术语冲突率 > 20% | 估算 < 10% | 否 |
| 不变量表达率 < 60% | 11 条不变量对应 4 个聚合，覆盖全面 | 否 |
| 集成模式与上下文映射不一致 | OHS+ACL+CS 与子域定位匹配 | 否 |
| 事件完整性 < 70% | 11 Booking + 4 Handling = 15 个事件，覆盖主 + 异常 + 回放 | 否 |

**结论：无系统性回溯触发**。P1–P6 为**微改**，不需要整条回溯链。

## 改进建议（不触发回溯的增量修复）

1. 将 `RouteCandidate` 从聚合表中移出，归入 Shipment 的 VO 章节并加粗"短生命周期"。
2. 在 `04-contexts` 增补第五个候选上下文"客户通知"，即使本期不单独实现也纳入路线图。
3. 与业务方确认 `HandlingType` 的最终枚举；若 `customs/inspection` 等需纳入则扩展 I-8。
4. 在 `07-domain-interactions` 对 "Late arrival 回放锚点" 补 1 段明确策略（建议以"最后一个未受影响的 handling"为锚点）。
5. `PortDirectory` 显式放入 Supporting 子域；若外部字典则升为 Generic。

## 反义词 / 禁用词表（Anti-Terms）

| 用词                                 | 为什么禁用                                         | 应改用                                                                                |
| :----------------------------------- | :------------------------------------------------- | :------------------------------------------------------------------------------------ |
| 跨上下文通用的"状态"                 | 每个上下文状态的含义不同，易引起混淆               | Booking 说"订单状态/路线版本"；Tracking 说"跟踪视图"；Handling 说"作业事实是否已接受" |
| "事件"（裸用）                       | 需区分"作业事实"（业务事实）与"领域事件"（发布物） | 作业事实 / 领域事件 分别命名                                                          |
| "路线"在 Pathfinder 中出现           | 路线是 Booking 的内部概念；外部返回的是"候选方案"  | 候选方案（外部）→ 路线（内部，防腐层后）                                              |
| 在 Tracking 中出现"判定/识别/重规划" | Tracking 不得承担判定权                            | 在 Booking 中表达                                                                     |
| 在 Handling 中出现"错卸/延迟"        | Handling 不做异常判定                              | 在 Booking 中表达                                                                     |

## 边界决策 ADR

### ADR-01：异常判定归属 Booking 而非 Handling

- **选项 A**：Handling 接收作业事实时就判"错卸"。
- **选项 B（选）**：Handling 只负责幂等吸收，Booking 订阅"已接受作业"事件后结合当前路线版本判定错卸。
- **理由**：判定需要"当前路线版本"，而路线在 Booking。把规则上推到 Booking 保证口径唯一，避免 Handling 复制路线数据；同时允许 Handling 在业务上保持通用、低复杂度。

### ADR-02：Tracking 视图只读，禁止承载任何判定

- **选项 A**：在 Tracking 中复制"错卸判定/ETA 计算"以优化读。
- **选项 B（选）**：Tracking 只从 Booking 发布的结果事件派生视图。
- **理由**：避免规则漂移；Tracking 归属前端团队，保留规则会造成三团队相互改业务逻辑的混乱。

### ADR-03：与 Pathfinder 建立防腐层

- **选项 A**：外部字段直通进入核心模型，快速接入。
- **选项 B（选）**：核心模型仅接受"路线草案"这一内部术语；由防腐层负责翻译/版本兼容/降级。
- **理由**：外部接口历史上已有过变更，且业务方明确"不让他们的改动随便打穿我们的系统"。

### ADR-04：一票货物（Shipment）与托运需求（ShippingRequest）分拆为两个概念

- **选项 A**：托运需求直接升格为订单，客户一提交就是订单。
- **选项 B（选）**：托运需求是询方案阶段的独立概念；订单在方案确认后才产生。
- **理由**：避免"未选方案的订单"这类不完整状态；对齐业务自然心智。

## 上下文间候选关系（供 `ddd-context-map` 细化）

- Booking ← Handling：上游-下游；Handling 为上游事实源，Booking 消费。
- Booking → Tracking：上游-下游；Booking 发布派生结果，Tracking 订阅并投影。
- Handling → Tracking：间接（经 Booking），Tracking 不直接读 Handling。
- Booking ↔ Pathfinder：Customer-Supplier + ACL，Booking 为客户，Pathfinder 为供应商。

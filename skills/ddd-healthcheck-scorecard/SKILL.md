# DDD Healthcheck Scorecard

## 使用时机

- 需要判断一个系统的 DDD 落地质量与主要风险来源。
- 需要为重构、拆分、治理提供可量化的评估与优先级依据。

## 输入要求

- 系统/业务概览、主要模块与依赖关系。
- 关键业务流程（事件流或用例列表）。
- 现有测试与发布流程信息（如有）。

## 流程

1. 战略维度评分：子域识别、上下文边界清晰度、通用语言一致性。  
2. 集成维度评分：上下文映射完整性、契约所有权、ACL 防护与版本策略。  
3. 战术维度评分：聚合边界、不变量表达、领域事件清晰度、仓储与事务边界。  
4. 工程维度评分：依赖方向合规、框架/ORM 侵入程度、模块循环依赖。  
5. 测试维度评分：核心域覆盖、Fail Fast 严格断言、契约测试与幂等验证。  
6. 汇总输出：分项得分、主要问题、整改切片路线与验收标准。  

## 输出

| 工件 | 结构要求 |
| :--- | :--- |
| 评分总览 | 0-10 分：战略、集成、战术、工程、测试 + 总分 |
| 问题清单 | 表格：问题、影响、证据、建议修复、优先级 |
| 整改路线 | 表格：切片、范围、依赖、风险、验收标准 |
| 复测口径 | 列表：如何重复评分、评分变化解释 |

## 校验清单

- [ ] 每个扣分项都提供可复核的证据与改进建议
- [ ] 整改路线可切片、可回滚、可验收
- [ ] 复测口径明确，评分可重复

## 常见陷阱

- 评分只给结论不给证据，无法驱动行动。
- 只关注工程层而忽略战略边界，导致“修好代码但修不好模型”。

## 示例

```text
使用 @ddd-healthcheck-scorecard 对当前系统做一次 DDD 体检：
输出分项 0-10 评分、证据化问题清单、可切片整改路线与验收标准。
```

# Event Storming Lite

## 使用时机

- 需要快速对齐业务流程，找到关键事件、命令与参与方。
- 需求涉及跨团队/跨系统协同，且对“发生了什么”缺少共同视角。

## 输入要求

- 业务场景描述（可从用户故事、PRD、工单中提取）。
- 关键参与方与外部系统（如已知）。
- 业务约束与非目标（来自阶段 0 输出）。

## 流程

1. 列出“已发生的事”（领域事件，过去式命名）。  
2. 为每个事件补齐：触发命令、参与角色、关键数据。  
3. 按时间顺序组织事件流，识别分支、回滚与异常路径。  
4. 标记“热点”：高频事件、强一致性点、跨系统边界点。  
5. 生成歧义清单：术语冲突、状态不清、责任边界不明。  
6. 产出下一阶段战略设计需要的候选能力与边界线索。

## 输出

| 工件 | 结构要求 |
| :--- | :--- |
| 事件流表 | 表格：序号、事件、触发命令、角色、输入/输出、异常分支 |
| 命令候选清单 | 表格：命令、发起方、期望结果、幂等性要求 |
| 事件候选清单 | 表格：事件、关键字段、是否跨上下文、是否对外发布 |
| 热点标注 | 列表：一致性热点、集成热点、性能热点、合规热点 |
| 歧义清单 | 表格：歧义点、影响、需要谁确认、建议决策 |

## 校验清单

- [ ] 事件采用过去式命名，且能被业务人员认可
- [ ] 至少覆盖 1 条主路径与 2 条异常/回滚路径
- [ ] 已标出跨系统边界点与强一致性点

## 常见陷阱

- 把“命令/动作”当作事件，导致事实与意图混淆。
- 只画主流程不讨论异常流程，后续集成成本暴涨。

## 示例

```text
使用 @ddd-event-storming-lite 为“退款申请到到账”做轻量事件风暴：
输出事件流表、命令/事件候选清单、热点与歧义清单。
```

# 01 — ddd-scope 产出（Blind Run）

> 输入：`00-fuzzy-prompt.md`。
> 本文件为 `ddd-scope` 在 blind run 下的模拟执行产出，**未参考**任何真值材料（本案例无参考实现）。

## 问题陈述与价值陈述

- **问题陈述**：承保与理赔环节信息断裂——核保人看不到完整历史赔付表现，理赔员拿不到准确条款信息，管理层无法实时掌握未决赔付规模，导致决策慢、差错多、监管报送被动。
- **价值陈述**：通过统一的"客户—保单—理赔"信息底座与全流程数字化，让核保决策有据、理赔处理准确、未决赔付实时可见，并满足监管报送要求。

## 目标 / 非目标

**目标**:

- 建立统一的客户—保单—理赔信息底座，跨环节自动关联（报案可关联到有效保单）。
- 支持核保决策全流程（接受 / 加费 / 限责 / 拒保 / 分保需求）。
- 支持理赔全流程（报案 → 查勘 → 定损 → 审批 → 支付 → 追偿），含欺诈调查挂起。
- 管理层实时掌握"已报案未赔付"规模与分布（准备金视角）。
- 满足监管数据报送与法定准备金计提要求。

**非目标**:

- 精算定价：费率由外部精算系统提供，本系统只消费费率结果（边界解释：避免把复杂精算模型纳入建模范围）。
- 投资与资金运用：财务资金操作在外部资金系统（边界解释：赔付支付只做指令与回执）。
- 经纪公司侧系统：通过接口交互，不做对方内部流程建模（边界解释：避免跨组织建模膨胀）。
- 人身险 / 健康险长尾流程：本案例聚焦财产险承保理赔主链。

## 约束与假设

| 约束 / 假设                                | 可验证性 | 验证方式                        |
| :----------------------------------------- | :------- | :------------------------------ |
| 监管要求保单与理赔数据按规范报送           | 可验证   | 对照监管报送规范核对字段清单    |
| 赔付支付需多级审批，大额需更高权限         | 可验证   | 与财务 / 合规确认审批层级表     |
| 报案入口需抗高峰并发且不可丢件             | 可验证   | 压测 + 事故复盘数据（巨灾场景） |
| 费率来自外部精算系统（假设）               | 可验证   | 确认接口契约存在且稳定          |
| 经纪公司通过接口交互（假设）               | 可验证   | 确认经纪侧接口文档              |
| 免赔额、等待期、除外责任为条款要素（假设） | 可验证   | 抽查在售保单条款样本            |
| 未决赔款准备金按法定方法计提（假设）       | 可验证   | 财务精算团队确认计提口径        |

## 术语种子清单

| 术语     | 定义候选                            | 歧义点                                       | 所属场景    |
| :------- | :---------------------------------- | :------------------------------------------- | :---------- |
| 客户     | 个人或企业投保主体                  | 同一主体在经纪渠道与直营渠道是否视为同一客户 | 投保        |
| 标的     | 被保险对象（车辆 / 财产 / 货物）    | 一标的多保单是否允许                         | 投保        |
| 投保申请 | 客户提交的承保请求                  | 与"报价"关系不明                             | 投保        |
| 报价     | 系统 / 核保人给出的费率方案         | 报价是否具约束力、有效期                     | 投保        |
| 核保     | 接受 / 加费 / 限责 / 拒保的决策过程 | 决策者是人还是规则引擎                       | 承保        |
| 分保     | 向再保险公司转移部分风险            | 分保是否影响对客决策结论                     | 承保        |
| 保单     | 成立的合同                          | 批改后是同一保单还是新保单                   | 保单管理    |
| 批改     | 保单条款的变更请求                  | 批改生效时点（申请时 / 审核时）              | 保单管理    |
| 续保     | 到期重新承接                        | 自动续保还是需确认                           | 保单管理    |
| 中止     | 欠费导致的保单失效                  | 中止后可否恢复                               | 保单管理    |
| 报案     | 客户提出损失主张                    | 一损失多次报案如何处理                       | 理赔        |
| 查勘     | 核定损失现场 / 线上核实             | 查勘结论与定损关系                           | 理赔        |
| 免赔额   | 损失低于此额不赔                    | 分次损失是否累计计算                         | 理赔        |
| 等待期   | 出单后一段内出险不赔                | 不同险种时长不同                             | 理赔        |
| 赔付     | 向客户支付赔款                      | 部分赔付与结案关系                           | 理赔        |
| 追偿     | 向责任方收回已赔款项                | 追偿款是否需冲减理赔成本                     | 理赔        |
| 未决赔款 | 已报案未赔付的金额                  | 口径（含不含已审批未支付）                   | 监管 / 财务 |

## 风险清单

| 风险                              | 影响                                | 触发条件                   | 缓解建议                                 |
| :-------------------------------- | :---------------------------------- | :------------------------- | :--------------------------------------- |
| 【业务】巨灾高峰报案超载          | 报案丢失 / 延迟，客户投诉与监管风险 | 台风等自然灾害             | 高并发架构、异步受理、峰值降级但不可丢件 |
| 【业务】重复 / 虚假报案           | 重复赔付、欺诈损失                  | 同一损失多次报案、夸大损失 | 报案合并识别、欺诈调查流程               |
| 【业务】条款状态冲突              | 错误赔付（批改与理赔并行时）        | 批改申请与报案同时发生     | 条款版本快照、生效时点规则               |
| 【集成】外部费率 / 经纪接口不稳定 | 报价与投保流程中断                  | 外部系统变更或故障         | 接口契约 + 超时降级 + 缓存               |
| 【集成】报送数据口径漂移          | 监管处罚                            | 口径规则与实现不一致       | 报送口径单一来源、定期对账               |
| 【一致性】未决赔款准备金不实时    | 管理层决策失真、计提不准确          | 报案 / 赔付数据延迟        | 准备金视图实时投影、对账                 |
| 【交付】审批链与系统解耦困难      | 赔付延迟                            | 审批依赖线下签字           | 电子审批流 + 审批链配置化                |

## 下一步准备清单

- **角色**：核保人、理赔员、客服（报案受理）、财务 / 合规（审批与报送）、运营（巨灾与异常处理）。
- **必要输入**：上述角色对术语种子清单歧义点的确认；真实保单条款样本（免赔额 / 等待期 / 除外责任样例）。
- **期望产出**：事件流表（主路径 + 异常分支）、命令 / 事件候选、热点与歧义清单（`ddd-discover`）。

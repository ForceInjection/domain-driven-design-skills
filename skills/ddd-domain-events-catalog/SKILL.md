# Domain Events Catalog

## 使用时机

- 需要用事件解耦聚合与上下文，建立最终一致的协作方式。
- 需要区分领域事件与集成事件，并明确哪些事件对外发布。

## 输入要求

- 事件候选清单（阶段 1）。
- 聚合清单与事务边界建议（阶段 4，如已完成）。
- 上下文映射与契约信息（阶段 3，如已完成）。

## 流程

1. 统一事件命名规则：过去式、业务可读、避免技术词。  
2. 为每个事件定义：触发条件、来源聚合、关键字段、时序要求。  
3. 区分范围：领域事件（上下文内）与集成事件（跨上下文/对外）。  
4. 定义发布边界与可靠性：幂等键、重放策略、去重策略、死信处理。  
5. 建立订阅者清单：消费者上下文、处理副作用、补偿策略。  
6. 输出事件契约：字段含义、版本策略、兼容窗口、弃用策略。  

## 输出

| 工件 | 结构要求 |
| :--- | :--- |
| 领域事件目录 | 表格：事件、来源聚合、触发条件、关键字段、范围 |
| 集成事件目录 | 表格：事件、发布方、消费者、契约 Owner、版本策略 |
| 幂等/重放策略 | 表格：事件、幂等键、去重窗口、重放规则、异常处理 |
| 订阅者与副作用 | 表格：事件、订阅者、动作、补偿、监控指标 |

## 校验清单

- [ ] 事件命名均为过去式，且无技术词污染
- [ ] 对外事件均定义版本策略与兼容窗口
- [ ] 关键事件提供幂等键与重放策略

## 常见陷阱

- 事件负载携带外部上下文的模型，造成领域泄漏。
- 未定义幂等与重放，导致重复消费与数据污染。
